# 栃木県公立高校入試問題精講・開発仕様書

## 0. この文書の役割
この文書は、KNOT Studyの「公立高校入試問題精講」を継続開発するための独立した仕様書。過去の会話を参照しなくても、対象・リポジトリ・既存実装・開発順序・品質基準が分かるようにする。高専対策「高専絶対合格」とは別プロジェクトとして扱う。

## 1. 固定情報
- GitHub: `knotspace/knotspace.github.io`
- URL: https://github.com/knotspace/knotspace.github.io
- ブランチ: `main`
- 公開サイト: https://knotspace.github.io/
- Studyトップ: `src/pages/study.astro`
- 公立入試演習: `src/pages/study/public-exam.astro`
- 過去問索引: `src/pages/study/past-exams.astro`
- 既存問題DB: `src/data/study/public-exam.json`、`src/data/study/public-exam-upgrade.json`
- 出題分析: `src/data/study/public-exam-focus.json`
- 共通解答UI: `src/styles/study/quiz-ui.css` および `src/pages/study/public-exam.astro` の既存実装
- 要点まとめ: `src/pages/study/summary/` 以下
- 必ず作業前にmainの最新状態と該当ファイルを読み、既存実装・データ形式を確認する。

## 2. 目的と対象
栃木県立高校入試を最優先に、5教科の過去問分析・教科別問題データベース・演習・解説を統合した教材を作る。将来ほかの都道府県を追加できる設計にするが、初期開発で全国対応を急がない。学習者が毎日使える実戦教材として、正確性・解説の質・操作性を最優先する。

## 3. 現状確認済みの実装
- 公立高校入試の演習ページはすでに存在する。
- `public-exam.json` は200問を収録する既存データ。
- `public-exam-upgrade.json` に追加問題がある。
- 現状ページは主に理科・社会の演習として実装され、画面上も教科選択が理科・社会に限定されている。
- `public-exam-focus.json` に栃木県入試の出題重点・根拠の一部が記録されている。
- `past-exams.astro` は年度別・教科別の過去問資料リンク索引。
- 既存UIは4択、即時採点、解説、苦手問題、学習記録を備える。これを壊さず拡張し、基礎網羅問題と操作感を統一する。
- 上記は開発開始時に必ず再確認し、件数や実装状態が変わっていれば最新コードを正とする。

## 4. 教科別データベース
数学・英語・国語・理科・社会を独立管理する。既存の互換性を保ちながら段階的に移行する。配置例:
- `src/data/study/public-exam/math/`
- `src/data/study/public-exam/english/`
- `src/data/study/public-exam/japanese/`
- `src/data/study/public-exam/science/`
- `src/data/study/public-exam/social/`
実際のAstroのimport・build方式に合わせ、JSON分割または適切なデータモジュールを選ぶ。5教科すべてで共通スキーマを使い、教科固有の補助情報は拡張フィールドにする。

### 問題データの必須項目
- 安定した一意ID
- prefecture（初期値 tochigi）、year、subject、unit/topic、subtopic
- difficulty（基礎・標準・応用・発展）
- questionType（知識・計算・資料読解・実験考察・長文読解・作文/記述等）
- prompt、options、correct（四択の場合）、解説
- solutionSteps、choiceNotes（誤答選択肢ごとの説明）
- relatedSummary、sourceType、sourceRef、sourcePage、sourceNote
- estimatedSeconds、tags、reviewStatus
- 図表・音声等のasset参照（必要な問題のみ）
記述問題など四択以外の形式は、採点基準・部分点基準・模範解答を保持できる形式を追加する。既存の`subject`値（science/social等）との互換変換を用意する。

## 5. 過去問の調査・分析
1. リポジトリ全体から過去問PDF・画像・正答・訂正資料・分析資料・出典リンクを探索する。
2. 年度・教科・本試験/追検査・大問・小問・ページ単位で確認状況を台帳化する。
3. 問題冊子と正答・採点資料・訂正通知を照合する。図表・グラフ・英文・会話文・資料は原本を目視し、OCRだけで断定しない。
4. 各小問について、単元、形式、必要知識、思考過程、難易度、配点（確認できる場合）、時間目安、正答根拠、誤答要因を記録する。
5. 複数年度を比較して出題の変化と継続テーマを整理する。確認できない年度・設問は推測せず「未確認」と記す。
6. 既存の`public-exam-focus.json`と重複・矛盾を照合し、根拠のない頻出断定を修正する。

## 6. 問題制作方針
- 過去問の分析を根拠に、基礎確認・標準・応用・発展の独自問題を作る。
- 元問題の数字や固有名詞だけを置き換える量産は禁止。問う能力・解法を分析し、設定・条件・資料・選択肢・図版を独自に設計する。
- 栃木県の出題形式・難易度・資料量・設問構成を参考にするが、公式問題と誤認させない。
- すべての問題に解答根拠、段階的な解説、誤答の理由、関連要点まとめ、難易度、出典またはKNOTオリジナル表示を付ける。
- 問題数のノルマは設けない。検証に通った問題だけを公開DBに入れる。
- 教科間で偏りが出ないよう、単元カバレッジ表を作り、未整備分野を可視化する。

### 教科別の制作重点
- 数学: 小問集合、計算、関数、図形、確率・統計、規則性、資料・グラフ。途中式と別解・誤答分析を重視。
- 英語: 語彙・文法だけに偏らず、対話文・長文・図表読解・語順整序・英作文を段階的に整備。英文の自然さ、設問根拠、語数条件を検証する。
- 国語: 説明的文章・文学的文章・古文/漢文（県の出題範囲・形式を確認）・漢字語句・文法・作文/記述。本文を扱う際は著作権に配慮し、独自文章を中心にする。記述は採点基準を用意する。
- 理科: 物理・化学・生物・地学。実験操作、観察結果、表・グラフ、計算、考察を組み合わせる。単なる用語一問一答に偏らない。
- 社会: 地理・歴史・公民・融合資料。地図・統計・年表・史資料の読解、複数資料の比較を重視する。統計値には年度・出典を付ける。

## 7. 権利・出典の扱い
- 公開GitHubに過去問原本PDFや著作物の長文・図版を無断転載しない。
- 原本の保存場所・公開条件・利用許諾を確認する。権利が不明な場合、出題分析メタデータと独自問題・独自図版を作成し、原本をそのまま再掲しない。
- 出典は実際に確認した資料だけを記録する。年度・教科・大問・小問・ページを推測しない。
- 公式問題、参考にした独自類題、完全オリジナル問題を明確に区別する。

## 8. 演習UI・学習機能
- 既存の解答UIを再利用し、スマホ・PCの両方で快適にする。
- 教科、単元、難易度、年度テーマ、問題形式、問題数で絞り込む。
- 4択以外の形式も必要性を検証して段階的に導入する。
- 正誤だけでなく、なぜその選択肢が正解/誤答なのかを表示する。
- 間違えた問題の復習、単元別正答率、解答時間、学習履歴を用意する。
- 問題解説から該当する要点まとめへ移動できるようにする。
- 5教科の模試形式・時間制限は、実際の栃木県入試の最新要項を確認して設計する。根拠なく試験時間や配点を固定しない。

## 9. 大容量データと速度
データ容量は5GBを超えることも許容するが、容量を増やすこと自体は目的にしない。GitHub通常ファイルのサイズ・リポジトリ肥大化・Git LFSの条件・Pagesのデプロイ制限・外部ストレージの料金と権限を確認する。問題DBを教科・年度・単元で分割し、必要なデータだけ遅延ロードする。画像は最適化し、重複データを避け、検索用インデックスを用意する。サイトの初期ロードを大きくしない。5GBを保存できると事前確認なしに断言しない。

## 10. 開発フェーズ
### Phase A: 現状棚卸し
既存ページ・DB・分析ファイル・リンク・テスト・過去問原本の配置を確認し、教科別の問題数と未整備分野をレポートする。

### Phase B: 分析台帳
確認可能な年度・教科の全大問・小問を分析し、出典付きの台帳とカバレッジ表を作る。

### Phase C: DB基盤
5教科共通スキーマ、教科別データ分割、重複検出、出典・検証ステータスを導入。既存問題を壊さず移行する。

### Phase D: 問題制作
まず既存の理科・社会の誤りと解説不足を監査し、その後、未整備の数学・英語・国語を優先して拡充する。各教科で基礎→標準→応用の順に品質検証済み問題を登録する。

### Phase E: UI統合
5教科選択、単元・難易度フィルター、学習記録、復習、要点まとめリンクを実装。既存ページを段階的に拡張し、動作を壊さない。

### Phase F: QAと公開
JSON/スキーマ、ID重複、選択肢数、正答index、解説、出典、リンク、図版、スマホ/PC、ビルドを検証する。未実行のテストを完了扱いしない。

## 11. 完了報告の必須項目
- 調査した過去問資料（年度・教科・ファイル名・確認ページ）
- 教科別の分析済み範囲と未確認範囲
- 教科別DBのパス・登録問題数・難易度内訳
- 新規制作問題数と検証済み問題数
- 既存問題の修正数
- 変更ファイルとコミットSHA
- 実行したテスト・ビルド・ブラウザ確認の結果
- 未解決事項・権利確認事項・次の作業

## 12. 開発AIへの最終指示
説明や計画だけで終わらず、リポジトリを読み、棚卸し、分析、DB設計、問題制作、実装、テスト、GitHub反映まで可能な範囲で連続して実行する。すでにコードや資料から分かることをユーザーに聞き返さない。破壊的変更・権利・費用など確認が必要な事項だけを切り分ける。変更していない機能を完成と報告しない。

**目標は、栃木県公立高校入試の5教科を、正確で分かりやすく、毎日の学習と本番得点につなげる高品質な教材にすること。**
